Protocol — ProofSpec

Open specification to prove when data existed and that it has not changed. Hash-only inputs, signed timestamps, public verification.

Overview

One proof to assert existence and immutability of data by timestamping its SHA-256 hash. The proof is self-describing and verifiable by any client.

Canonicalization

  • Hash input is raw byte content. For text, normalize to UTF-8 without BOM.
  • For JSON meta, use stable key order when computing additional digests.

Data model

{
  "hash": "<64-hex>",                   // SHA-256 of original bytes
  "ts": "2025-01-01T00:00:00.000Z",     // ISO 8601 UTC timestamp
  "sig": "",                       // signature over "hash|ts"
  "alg": "HMAC-SHA256",                 // or "Ed25519" (planned)
  "kid": "v1",                          // key id / version
  "issuer": "timeproofs.io",            // signer identifier
  "type": "event",                      // optional semantic tag
  "meta": { "source": "web" }           // optional, avoid PII
}

Proof format

JSON object. Required: hash, ts, sig. Optional: alg, kid, issuer, type, meta, verify_url.

Signing

// message = `${hash}|${ts}`
HMAC_SHA256(secret, message) -> hex             // current
Ed25519.sign(privateKey, message) -> hex        // roadmap

Validation

  1. Check hash matches ^[a-f0-9]{64}$.
  2. Parse ts as RFC 3339 / ISO 8601 UTC.
  3. Recompute signature with key resolved by kid.
  4. Optionally, check verify_url returns a consistent status.

JSON schema

{
  "$schema":"https://json-schema.org/draft/2020-12/schema",
  "type":"object",
  "required":["hash","ts","sig"],
  "properties":{
    "hash":{"type":"string","pattern":"^[a-f0-9]{64}$"},
    "ts":{"type":"string","format":"date-time"},
    "sig":{"type":"string","pattern":"^[a-f0-9]+$"},
    "alg":{"type":"string"},
    "kid":{"type":"string"},
    "issuer":{"type":"string"},
    "type":{"type":"string"},
    "verify_url":{"type":"string","format":"uri"},
    "meta":{"type":"object","additionalProperties":true}
  },
  "additionalProperties":false
}

Test vectors

// Text: "TimeProofs"
hash = 7c040f8633b8823d72ed63da9b3b2dfe9846e912c66a64c9433ec9c4815d76c2
ts   = 2025-01-01T00:00:00.000Z
sig  = HMAC_SHA256(secret, `${hash}|${ts}`)

Verification

GET  https://api.timeproofs.io/api/verify?hash=<64-hex>
POST https://api.timeproofs.io/api/verify
Body: {"hash":"<64-hex>"}

Verify URL

Producers SHOULD include verify_url so any client can fetch a human- and machine-readable result.

Proof bundle

Array of proof objects. Each proof must validate independently. Order does not matter.

Reserved fields

  • Private/vendor fields MUST use x-* or begin with _.
  • Field names are case-sensitive UTF-8 strings.

Errors

{"ok":false,"error":"invalid_signature"}
{"ok":false,"error":"not_found"}
{"ok":false,"error":"rate_limited"}

Operational policy

  • Public verification endpoints.
  • Adaptive rate limits per IP/key.
  • Key rotation via kid. JWKS for Ed25519 is planned.
  • Minimal logs. No original content ever uploaded.

Checklist

  • Hash locally using SHA-256.
  • Sign server-side over hash|ts.
  • Return proof JSON + verify_url.
  • Provide test vectors.

Versioning

Spec: v0.1. Breaking changes will bump minor until 1.0.
