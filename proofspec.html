Protocol — ProofSpec

Open specification to prove when data existed and what has not changed. Hash-only inputs, signed timestamps, public verification.

Overview

ProofSpec defines a minimal, interoperable tuple for proof of existence. Implementations MUST NOT upload original content. All verification steps are public and deterministic.

  • Input: SHA-256 hash of caller-provided content.
  • Output: signed tuple and a stable verification URL.
  • Privacy: content never leaves the device.

Proof format

{
  "hash": "7c040f8633b8823d72ed63da9b3b2dfe9846e912c66a64c9433ec9c4815d76c2",
  "ts": "2025-01-01T00:00:00.000Z",
  "sig": "",
  "alg": "HMAC-SHA256",
  "kid": "v1",
  "issuer": "timeproofs.io",
  "meta": {"source":"web"},
  "verify_url": "https://api.timeproofs.io/api/verify?hash=..."
}

Canonical message for signing is:

message = `${hash}|${ts}`

Signing

  • Required: HMAC-SHA256.
  • Planned: Ed25519 with public JWKS for detached verification.
  • Keys MUST rotate with distinct kid values.
// Node.js reference
import crypto from "node:crypto";
export function sign(hash, ts, secret){
  return crypto.createHmac("sha256", secret)
    .update(`${hash}|${ts}`).digest("hex");
}

Verification

  1. Validate input: hash is 64 lower-hex, ts is ISO-8601 UTC.
  2. Recompute expected signature from hash|ts.
  3. Compare using constant-time equality.
  4. Optionally call verify_url for status replication.
// Pseudocode
ok = timingSafeEqual(sig, HMAC_SHA256(secret, `${hash}|${ts}`))

API mapping

  • POST /api/timestamp → returns proof tuple.
  • GET /api/verify?hash=… → public status.

Compatibility

ProofSpec is transport-agnostic. Files, text, and binary inputs are supported as long as the client computes SHA-256 consistently.

Security considerations

  • No original content transfer. Hash-only boundary.
  • Time source MUST be UTC. Tolerance during verify is implementation-defined.
  • Replay is harmless due to idempotency on identical hash.

Conformance

Implementations claiming “ProofSpec-compatible” MUST produce and verify tuples per sections Model, Format, Signing, and Verification.

Versioning

  • Draft: v1.
  • Breaking changes will increment major or introduce a new kid/algorithm.
