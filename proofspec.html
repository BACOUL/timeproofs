ProofSpec v0.1

Open, minimal protocol to prove when data existed and that it has not changed. Hash-only input. Signed timestamps. Public verification.

1. Goals

  • Privacy-first: originals never leave the device.
  • Auditability: anyone can verify with public endpoints.
  • Interoperability: one self-describing JSON proof.
  • Simplicity: minimal fields, stable semantics.

3. Proof Format (JSON)

{
  "hash": "<64-hex>",
  "alg": "HMAC-SHA256",
  "ts": "2025-01-01T00:00:00.000Z",
  "sig": "",
  "kid": "v1",
  "issuer": "timeproofs.io",
  "meta": { "type":"event", "source":"cli" },
  "verify_url": "https://api.timeproofs.io/api/verify?hash=<64-hex>"
}

3.1 Canonical message

message = hash + "|" + ts

4. Algorithms

  • Hashing: SHA-256.
  • Signatures: HMAC-SHA256 now; Ed25519 planned via public JWKS.
// Node.js verify (HMAC)
import crypto from "node:crypto";
function verify({hash, ts, sig}, secret){
  const msg = `${hash}|${ts}`;
  const expect = crypto.createHmac("sha256", secret).update(msg).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(expect,'hex'), Buffer.from(sig,'hex'));
}

6. Interoperability

  • Self-describing JSON enables independent validation.
  • Stable canonical message avoids ambiguity.
  • Reference API conforms to ProofSpec; clients may self-host.

7. Security considerations

  • No original content uploaded. Only hashes and minimal fields.
  • Enforce per-IP/key rate limits. Idempotency for same hash.
  • Rotate keys and version via kid. Public JWKS for Ed25519 when enabled.
  • Verify with constant-time comparisons.
