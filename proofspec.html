Use Cases

The simplest question: When did this exact data exist? And later: Has it changed? TimeProofs answers both using a verifiable timestamp on a SHA-256 hash — without seeing your data.

Overview

TimeProofs is not a file date. A file date is local, editable, and not independently verifiable. A TimeProofs proof is a signed timestamp tied to the exact SHA-256 hash of your bytes.

Typical flow:

  • Hash locally (your data stays on your device).
  • Timestamp the hash via the stateless API v0.2.
  • Store the proof JSON (or portable .tproof.json bundle).
  • Anyone can verify later (online via verify URL, or offline by inspecting the proof).

AI outputs (prompts, generations, pipelines)

Goal: prove when an AI output existed (and that it hasn’t changed), without uploading the text, image, or dataset itself.

Examples:

  • Timestamp a generated report, summary, or decision log.
  • Timestamp prompts and system instructions for traceability.
  • Attach a proof bundle to each pipeline run for audits.
# Example: timestamp an AI output (hash locally, then call the API)
HASH=$(printf "%s" "$OUTPUT" | sha256sum | awk '{print $1}')
curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"$HASH\",\"type\":\"ai\",\"meta\":{\"model\":\"example\",\"source\":\"pipeline\"}}" \
  -o output.tproof.json

Software releases (build integrity)

Goal: prove exactly which artifact was shipped, and when.

  • Timestamp build outputs (binaries, bundles, Docker images digests).
  • Publish verify links in release notes.
  • Archive proofs with SBOMs or compliance packages.
# Example: timestamp a build artifact
HASH=$(sha256sum dist/app.min.js | awk '{print $1}')
curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"$HASH\",\"type\":\"release\",\"meta\":{\"env\":\"prod\"}}" \
  -o release.tproof.json

Audit trails (policies, filings, evidence)

Goal: maintain a tamper-evident record that a specific document version existed at a given time.

  • Timestamp a PDF policy, NDA, or disclosure before publishing.
  • Timestamp incident reports and postmortems.
  • Provide verifiable proof without sharing the original document publicly.

Important: TimeProofs provides cryptographic integrity evidence. It does not provide identity verification, delivery guarantees, or legal notarization.

Creators (media, writing, certificates)

Goal: prove a work existed at a point in time, without watermarking or exposing raw files to a third party.

  • Timestamp images, videos, audio, designs, manuscripts.
  • Ship a .tproof.json bundle alongside the file as a portable receipt.
  • Let anyone verify the work later by re-hashing the file and checking the proof.

Datasets (research, ML training, snapshots)

Goal: prove dataset versions and model inputs are immutable across time.

  • Timestamp dataset snapshots (CSV/Parquet/ZIP manifests).
  • Timestamp training configs and evaluation outputs.
  • Use verify URLs for reviewers/auditors without exposing raw data.

Supply chain (vendor deliverables, configs, SBOMs)

Goal: prove that deliverables shared between organizations are exact and unchanged.

  • Timestamp vendor deliverables (packages, documents, compliance bundles).
  • Timestamp critical configuration exports and baselines.
  • Publish proofs for root transparency files (e.g. security.txt, integrity.txt).

How to use (minimal)

1) Hash locally

Compute a SHA-256 hash on your device. Do not upload the original content.

2) Timestamp the hash

curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"<64-hex>\"}"

3) Verify later

GET https://api.timeproofs.io/api/verify?hash=<64-hex>

Tip: store the returned JSON as a portable receipt (.tproof.json) next to your artifact.
