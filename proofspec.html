Protocol — ProofSpec

Open specification to prove when data existed and that it has not changed. Hash-only inputs, signed timestamps, public verification.

Overview

Hash locally → get a signed timestamped proof → anyone can verify later without your data.

Canonicalization

  • Bytes-in, bytes-out. Hash exact bytes.
  • Text: UTF-8, normalize line endings to LF.
  • JSON meta: stable key order if pre-hashed.

Data model

FieldTypeNotes

tsISO 8601UTC timestamp

Proof format

{
  "hash":"<64-hex>",
  "ts":"2025-01-01T00:00:00.000Z",
  "sig":"<hex>",
  "alg":"HMAC-SHA256",
  "kid":"v1",
  "issuer":"timeproofs.io",
  "verify_url":"https://api.timeproofs.io/api/verify?hash=..."
}

Signing

// Node.js HMAC verify
import crypto from "node:crypto";
function verify({hash, ts, sig}, secret){
  const msg = `${hash}|${ts}`;
  const expect = crypto.createHmac("sha256", secret).update(msg).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(expect,'hex'), Buffer.from(sig,'hex'));
}

Validation

  • Hash is 64 hex.
  • ts is ISO-8601 UTC and not in the future beyond tolerance.
  • Recompute expected signature for the given alg and kid.

Verification

GET /api/verify?hash=<64-hex>
→ {"ok":true,"valid":true,"timestamp":"..."}

Verify URL

Stable endpoint that returns JSON status for the given hash. Link included in the proof JSON.

Proof bundle

Ship artifacts with their .tproof.json or embed only the verify link.

Reserved fields

Names starting with _tp_ are reserved for the spec.

Errors

{"ok":false,"error":"invalid_hash"}

Operational policy

  • Minimal logs
  • Rate limits
  • Key rotation with kid

Checklist

  • Hash locally
  • Keep proof JSON
  • Verify URL present

Versioning

Spec v0.1. Additive changes when possible. Breaking changes bump major.
