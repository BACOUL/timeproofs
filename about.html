About TimeProofs

Mission, values, governance, and transparency behind TimeProofs — the open, privacy-first standard for digital proof of existence, compatible with a stateless API v0.2 and portable .tproof.json proof files.

Mission

Why TimeProofs exists

TimeProofs provides a simple, verifiable way to prove that a piece of data existed at a specific time and has not changed — without uploading the original content.

It is built as the reference implementation of an open protocol called ProofSpec.

What it is (and what it isn’t)

It is: hash-only proofs, signed timestamps, open verification, privacy-first design.

It isn’t: a blockchain, a token system, a content storage service, or a legal certification authority.

Values

Privacy-first

Only hashes are processed. Your original files, prompts, or datasets do not need to leave your device.

Open verification

Proofs are designed to be checked independently. The format is meant to outlive any single provider.

Minimalism

Keep the protocol simple enough to become a standard: stable rules, predictable cost, and clear interoperability.

Governance

Reference implementation

TimeProofs is maintained as a reference implementation of ProofSpec, with an open standard roadmap aiming at community governance over time.

Roadmap (high-level)

v0.1 → public MVP
v0.2 → stateless bundles (.tproof.json) + offline verification patterns
v1.0 → dashboard + keys + billing (implementation detail)
v2.0 → distributed validation (ProofChain)
v3.0+ → governance + standardization tracks

FAQ

Do you store my content?

No. TimeProofs is designed to process hashes only. Originals never need to leave your device.

Is TimeProofs a blockchain?

No. It uses signed cryptographic timestamps with public verification.

Can I self-host?

Yes. The goal is interoperability: you can implement ProofSpec and run compatible infrastructure.
