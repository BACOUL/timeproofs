Use Cases

Where TimeProofs fits today: AI provenance, prompt and event logs, data integrity at exchange, and verifiable software releases.

Proof of Release Release: · Hash: Verify

Overview

Model: Hash locally → Signed timestamp → Public verification. Nothing private leaves the device. Anyone can verify with only the SHA-256 hash.

Key use cases

AI Outputs Provenance

Timestamp AI outputs so you can prove when they existed and that they haven’t changed.

Type: gen
Meta: {"model":"...", "mime":"text/markdown"}
Verify: /api/verify?hash=<sha256>

Prompt & Event Logs

Sign prompts or events without storing content. Keep ordered evidence of interactions.

Type: prompt or event
Meta: {"source":"app","redact":true}
Verify: GET /api/verify

Data Exchange

Attach a proof to datasets, documents, or binaries exchanged across orgs.

Type: file
Bundle: .tproof.json alongside file
Verify: GET /api/verify?hash=...

Release Integrity

Publish a proof for each build. CI/CD and customers verify public logs.

Type: release
Meta: {"version":"vX.Y.Z","commit":"..."}
Verify: curl -sS "…/verify?hash=..."

How to verify a proof

1) Copy the SHA-256 hash. 2) Open /api/verify?hash=<HASH>. 3) Confirm valid:true and timestamp.

GET https://api.timeproofs.io/api/verify?hash=<SHA256-hex>
Accept: application/json
