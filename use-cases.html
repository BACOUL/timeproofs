Use Cases

Where proof of existence adds value: AI provenance, audit trails, secure releases, creators, datasets, and supply chain integrity — powered by a stateless API and portable .tproof.json receipts.
Key idea: a file date is local and editable; TimeProofs proves when an exact content existed using a verifiable timestamp on its SHA-256 hash.

1) AI provenance (prompts, outputs)

What it solves. Prove origin and integrity for prompts, model outputs, and intermediate artifacts. Share a public verify URL without exposing content.

Why TimeProofs. Local hashing, signed edge timestamp, and open verification make AI activity auditable without leaking data. With v0.2, you also get a portable .tproof.json receipt that can travel with each run.

Important: the timestamp applies to the hash (a 64-hex digest), not to the raw prompt/output. TimeProofs never receives your original content. 

// How it works (API v0.2, stateless)
1) Client hashes prompt or output bytes (SHA-256).
2) POST /api/timestamp { hash, type:"ai", meta:{ model:"gpt-4o", run:"2025-11-07" } }
3) Store the proof JSON or a .tproof.json receipt with the run metadata.
4) Later, verify via the public endpoint or any offline ProofSpec verifier.
# Shell snippet
HASH=$(printf "%s" "$OUTPUT" | sha256sum | awk '{print $1}')
curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"$HASH\",\"type\":\"ai\",\"meta\":{\"model\":\"my-model\"}}" \
  -o run.tproof.json

Compliance: supports traceability needs (EU AI Act / audits). GDPR: hash-only, no model inputs or outputs stored by TimeProofs.

2) Audit trails (compliance, evidence chains)

What it solves. Tamper-evident proof records for filings, evidence chains, policies, NDAs, and disclosures, without uploading the documents.

Why TimeProofs. Time anchoring with public verification, zero content retention, and a standard JSON proof format that can live in your own archives.

Note: TimeProofs provides cryptographic integrity evidence (hash + signed timestamp). It does not provide legal qualification, identity verification, or “notarization”. 

// Process
- Hash each PDF, contract, or policy file locally.
- Timestamp the hash via TimeProofs (get proof JSON or .tproof.json).
- Archive the proof alongside the case or policy dossier.
- Share the verify URL or the .tproof.json file with auditors or third parties.

Regulatory posture: supports integrity and prior existence within your compliance chain, without forcing content disclosure.

3) DevOps & secure releases

What it solves. Build and artifact integrity across CI/CD pipelines. Prove what was deployed, when, and from which artifact hash.

Why TimeProofs. Edge timestamps under 100 ms, a stateless verify API, and proof bundles you can attach to release notes or SBOMs.

This makes “what was deployed” independently verifiable: if the artifact bytes change, the hash changes, and verification fails. 

# CI sample (bash)
HASH=$(sha256sum dist/app.min.js | awk '{print $1}')
curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"$HASH\",\"type\":\"release\",\"meta\":{\"source\":\"ci\",\"env\":\"production\"}}" \
  -o release.tproof.json

Compliance: supports SBOM attestations and supply-chain security programs.

4) Creators & media certificates

What it solves. Portable “proof bundles” for images, audio, video, and documents. You can prove you created or published something at a given time.

Why TimeProofs. Hash-only provenance and a simple .tproof.json bundle you can distribute with your work or store in your own vault.

A local file date can be edited. A proof is public and verifiable: anyone can check the timestamp record matches the hash of the exact bytes. 

// Example example-photo.tproof.json (envelope + ProofSpec proof)
{
  "artifact_name":"my-photo-01.jpg",
  "artifact_type":"image",
  "created_at":"2025-01-01T00:00:00.000Z",
  "creator_handle":"@handle",
  "proof":{
    "hash":"<64-hex>",
    "ts":"2025-01-01T00:00:00.000Z",
    "sig":"<hex>",
    "alg":"HMAC-SHA256",
    "kid":"v1",
    "issuer":"timeproofs.io",
    "verify_url":"https://api.timeproofs.io/api/verify?hash=..."
  }
}

You keep the files. The world only sees hashes, proof bundles, and verify URLs.

5) Data & research integrity

What it solves. Snapshot datasets, notebooks, and analysis outputs. Enable peers and reviewers to verify that what they see matches what was certified.

If a dataset changes by a single byte, its hash changes. A proof tied to the old hash won’t validate the new bytes. 

# Dataset example
HASH=$(sha256sum data.csv | awk '{print $1}')
curl -s https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d "{\"hash\":\"$HASH\",\"type\":\"dataset\",\"meta\":{\"version\":\"v1\",\"project\":\"study-42\"}}" \
  -o dataset.tproof.json

Any ProofSpec-compliant verifier can check the proof later, even offline.

6) Supply chain transparency

What it solves. Publish proofs for SBOMs, licenses, vendor deliverables, and configuration baselines.

This creates a verifiable baseline: partners can independently confirm they received the exact same deliverable. 

// How it works
- Hash SBOM JSON, license packs, or configuration exports.
- Timestamp each hash (get proof JSON or .tproof.json).
- Include verify URLs and/or tproof files in procurement docs and SLAs.

Helps demonstrate integrity across vendors and internal teams, without forcing you onto a specific infrastructure.

Supported root protocols

TimeProofs can timestamp and verify the integrity of several root-level transparency files that live at the top of a domain. These protocols are independent standards; TimeProofs does not own them, but can provide ProofSpec-based proofs for their contents.

  • robots.txt — crawler and indexing rules.
  • security.txt — security contact and disclosure policy.
  • integrity.txt — tracking, cookies, logs, third-parties, and security posture.
  • authenticity.txt — how humans and AI collaborate on content creation.
  • rights.txt — usage rights, licences, and allowed/forbidden scenarios.
  • explainable-ia.txt — AI systems in use, input/output handling, explanations, limitations.
  • humans.txt — human credits and ethical commitments.

A typical pattern: hash the file (for example integrity.txt), obtain a ProofSpec proof or .tproof.json receipt, and publish the verify URL next to the file. Any verifier can then check that the root protocol file itself has not been tampered with.

Compare options

TimeProofs. Hash-only, signed timestamp, stateless verify, public API, no blockchain, privacy-first.

Traditional notarization. Manual, costly, sometimes requires content exposure.

Blockchains. Heavy, fees, latency, and potential PII or metadata leakage.

If you need identity checks, signatures, delivery guarantees, or legal qualification, those are separate layers outside TimeProofs.

Quick FAQ

Do you store my files? No. Only hashes. Original content never leaves your device.

Can anyone verify a proof? Yes. Use the public verify endpoint or any ProofSpec-compliant client, online or offline.

How fast are timestamps? Typical edge latency under 100 ms.

What about key rotation? Signatures support key IDs; verification remains stable across rotations.
