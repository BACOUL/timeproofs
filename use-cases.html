How it works

1) Hash locally

const buf = new TextEncoder().encode(textOrBytes);
const digest = await crypto.subtle.digest('SHA-256', buf);
const hash = [...new Uint8Array(digest)].map(b=>b.toString(16).padStart(2,'0')).join('');

2) Timestamp

const r = await fetch("https://api.timeproofs.io/api/timestamp", {
  method:"POST", headers:{ "Content-Type":"application/json","Accept":"application/json" },
  body: JSON.stringify({ hash, type:"event", meta:{ source:"web:use-cases" } })
});
const proof = await r.json();

3) Verify anywhere

const res = await fetch(
  "https://api.timeproofs.io/api/verify?hash="+hash,
  { headers:{ "Accept":"application/json" } }
);
const check = await res.json();

Share a bundle

// .tproof.json portable file
{
  "version":"v0.1","hash":hash,"algorithm":"SHA-256",
  "timestamp":proof.timestamp,"signature":proof.signature,"signer":"TimeProofs",
  "meta": proof.meta
}

FAQ — Use cases

Is timestamping enough for AI provenance?

For traceability and integrity checks, yes. If you need identity assurance, pair with your own signing keys.

Can I verify offline?

v0.1 uses the verify API. v0.2 adds offline/bundle verification with published key metadata.

What about personal data?

Do not include PII in meta. Hash-only model avoids sending content.

How do I integrate in CI/CD?

Hash build artifacts, call /timestamp, publish verify links in release notes.
