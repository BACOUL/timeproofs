Overview

What it solves

Authenticity in an AI-generated world. Fast, private, and verifiable proof of existence.

Model: Hash locally → Signed timestamp → Public verification.

Why it fits anywhere

Hash-only privacy, open JSON, and a public verify endpoint. No blockchain, no vendor lock-in.

AI outputs provenance

What

Timestamp model outputs, prompts, and system messages to prove when a result existed.

How

// Client
const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(output));
const hash = [...new Uint8Array(digest)].map(b=>b.toString(16).padStart(2,'0')).join('');
// Server
fetch('https://api.timeproofs.io/api/timestamp', {
  method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({ hash, type:'gen', meta:{ model:'gpt-4o-mini' } })
});

Why

Meets AI traceability. Enables audits and downstream trust without leaking content.

Tip: store the hash alongside internal IDs only.

Datasets & data sharing

What

Publish dataset snapshots with a public proof URL. Consumers verify integrity at fetch time.

How

{
  "hash": "sha256-hex-of-archive",
  "type": "dataset",
  "meta": { "name": "corpus-v2", "rows": 125004 }
}

Why

Provenance for ML and analytics pipelines. Simplifies change management and reproducibility.

Releases & supply chain

What

Signpost proofs for website builds, binaries, and artifacts. Link verify URLs in changelogs.

How

// CI step
curl -sS -X POST https://api.timeproofs.io/api/timestamp \
 -H 'Content-Type: application/json' \
 -d '{"hash":"<sha256-hex>","type":"release","meta":{"ci":"github-actions"}}'

Why

Strengthens supply chain integrity. Public attestation without exposing internal archives.

Contracts & e-records

What

Prove the state of a PDF or record at a moment in time. Store only the hash.

How

{
  "hash":"sha256-hex-of-pdf",
  "type":"file",
  "meta":{"mime":"application/pdf","title":"MSA-2025"}
}

Why

Integrity evidence for audits and disputes, with zero personal data on the proof layer.
