Overview

Model: hash locally → get a signed timestamp (proof) → anyone can verify later.

Important: a file date is local, editable, and not independently verifiable. A TimeProofs proof is a signed timestamp for an exact hash that third parties can verify.

TimeProofs is hash-only. Your original content stays on your device.

1) AI outputs & agent traces

What you prove

  • When an exact output (or prompt) existed.
  • That it hasn’t changed since.

How

  • Hash the bytes of the output (SHA-256).
  • Timestamp the hash via the API.
  • Store the proof JSON next to your run logs.

Artifact: keep a .tproof.json bundle and/or a verify URL.

2) Audit trails & compliance

What you prove

  • Prior existence of a policy, decision, report, or disclosure.
  • Integrity across reviews and revisions (by versioned hashes).

How

  • Hash each finalized PDF/export.
  • Timestamp each hash.
  • Attach proofs to the audit record.

Artifact: .tproof.json per document version.

3) Releases & builds

What you prove

  • Which artifact was shipped (exact hash).
  • When it was issued (signed timestamp).

How

  • Hash your build output (binary / bundle / SBOM).
  • Timestamp the hash.
  • Publish the verify URL in release notes.

Artifact: release bundle hash + .tproof.json proof.

4) Creators & deliverables

What you prove

  • When a specific work (image/audio/doc) existed.
  • That distributed copies match the certified original hash.

How

  • Hash the exported file.
  • Timestamp the hash.
  • Ship the proof alongside the file.

Artifact: work.ext + work.ext.tproof.json.

5) Datasets & research

What you prove

  • When a dataset snapshot existed.
  • That the dataset used for an analysis is the same later.

How

  • Hash the dataset file(s) or an archive/manifest.
  • Timestamp the hash.
  • Reference the proof in papers, model cards, or registry entries.

Artifact: dataset manifest hash + proof bundle.

6) Supply chain & vendor artifacts

What you prove

  • Integrity of delivered packages, SBOMs, and configs.
  • Traceable issuance timestamps across vendors.

How

  • Hash each deliverable (SBOM, license pack, config export).
  • Timestamp the hash.
  • Share verify URLs in procurement/SLA documentation.

Artifact: vendor deliverable hash + proof bundle.

Recommended workflow

  1. Hash locally (SHA-256) the exact bytes you care about.
  2. Create a proof via Create / Verify or the API.
  3. Store the .tproof.json next to the artifact.
  4. Verify later: offline inspection (bundle) + optional online verification (verify URL).

Best practices

  • Canonicalization: for text, prefer UTF-8 and normalize line endings (LF) before hashing.
  • No personal data: keep metadata small and avoid PII.
  • Keep bundles: store proofs with artifacts (not only a URL).
  • Stability: use a consistent hashing workflow so results are reproducible.

Mini FAQ

Do you store my files? No. TimeProofs is hash-only.

Is a file date enough? No. File dates are editable; proofs are signed and verifiable.

Blockchain required? No.
