Start (30 seconds)

Key point (v0.2): the response of POST /api/timestamp is the proof bundle.

TimeProofs returns a self-contained .tproof.json that you store next to your file, output, dataset, model card, or release artifact. There is no separate “bundle step”: the API response is already the portable proof. 

Flow (v0.2)
1) Hash locally (SHA-256 hex, 64 chars)
2) POST /api/timestamp with the hash (+ optional meta)
3) Store returned .tproof.json bundle next to the artifact
4) Verify later (offline or via /api/verify)

A file creation date is local and editable. TimeProofs proves when an exact hash existed — independently verifiable by third parties.

Endpoints

POST /api/timestamp

Create a signed proof bundle for a SHA-256 hash.

Request (JSON)
{
  "hash": "64 lowercase hex (sha-256)",
  "type": "event | file | release | dataset | ai-output | ...",
  "meta": { "source": "optional" }
}
Response (JSON)
{
  "hash": "…",
  "ts": 1730793600000,
  "alg": "HMAC-SHA256",
  "sig": "base64url(...)",
  "issuer": "timeproofs.io",
  "type": "event",
  "meta": { "source": "…" },
  "verify": "https://api.timeproofs.io/api/verify?hash=…"
}

The signature is defined by ProofSpec and is treated as opaque by clients. For independent checks, use the verify endpoint or an offline verifier.

GET /api/verify?hash=<sha256>

Verify a hash online (public verification).

Response (JSON)
{
  "ok": true,
  "hash": "…",

Quickstart

cURL

curl -X POST "https://api.timeproofs.io/api/timestamp" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "hash":"<your_sha256_hex>",
    "type":"event",
    "meta":{"source":"quickstart"}
  }'

JavaScript (browser / workers)

// 1) Hash locally (SHA-256)
const buf = new TextEncoder().encode("hello");
const digest = await crypto.subtle.digest("SHA-256", buf);
const hash = [...new Uint8Array(digest)].map(b => b.toString(16).padStart(2,"0")).join("");

// 2) Timestamp
const r = await fetch("https://api.timeproofs.io/api/timestamp", {
  method: "POST",
  headers: { "Content-Type":"application/json", "Accept":"application/json" },
  body: JSON.stringify({ hash, type:"event", meta:{ source:"web" } })
});

// v0.2: API response is the portable proof bundle
const proof = await r.json();

v0.2 public beta does not require API keys.

Proof bundle format (.tproof.json)

Rule (v0.2): API responses use ts as Unix epoch milliseconds. Portable .tproof.json bundles store ts as ISO-8601 UTC (string) for readability. 

{
  "version": "v0.2",
  "hash": "^[a-f0-9]{64}$",
  "ts": "2025-12-25T00:00:00.000Z",
  "alg": "HMAC-SHA256",
  "sig": "base64url(...)",
  "issuer": "timeproofs.io",
  "type": "event",
  "meta": { "source": "…" },
  "verify": "https://api.timeproofs.io/api/verify?hash=…"
}

Keep meta small and non-sensitive. Do not include personal data.

Verification (online and offline)

Online verification

curl "https://api.timeproofs.io/api/verify?hash=<sha256_hex>" \
  -H "Accept: application/json"

Offline verification

Offline verification means verifying the .tproof.json locally using a ProofSpec-compliant verifier. The verifier checks the bundle integrity and signature rules without contacting the API.

Use the Create / Verify tool for offline checks in the browser.

FAQ

Do you store my data?

No. TimeProofs only processes hashes. The original content stays on your device.

Is there a blockchain?

No. Proofs are signed cryptographic timestamps with public verification.

Is TimeProofs a legal notarization?

No. TimeProofs provides a technical proof of existence and integrity (hash + time + verifiable signature). It does not claim legal notarization or legal value.

Can I self-host?

Yes. Use the OpenAPI spec and ProofSpec to run a compatible implementation and interoperate.
