1) Start here (30 seconds)

TimeProofs is hash-only. You compute a SHA-256 on your device, the API signs a timestamp for that hash, and anyone can verify later.

1) Hash locally (SHA-256 hex, 64 chars)
2) Timestamp: POST /api/timestamp { hash, meta? }
3) Verify:    GET  /api/verify?hash=...

File dates are local and editable. TimeProofs proves when an exact content hash existed — publicly verifiable.

2) Quickstart (copy/paste)

Timestamp (cURL)

curl -s -X POST https://api.timeproofs.io/api/timestamp \
  -H "Content-Type: application/json" \
  -d '{"hash":"<SHA256_HEX>","meta":{"type":"file"}}'

Verify (cURL)

curl -s "https://api.timeproofs.io/api/verify?hash=<SHA256_HEX>"

Hash a string (Browser JS)

async function sha256Hex(str){
  const buf=new TextEncoder().encode(str);
  const digest=await crypto.subtle.digest("SHA-256", buf);
  return [...new Uint8Array(digest)].map(b=>b.toString(16).padStart(2,"0")).join("");
}

Timestamp (Browser JS)

const API="https://api.timeproofs.io/api";
const hash=await sha256Hex("hello");

const proof=await fetch(`${API}/timestamp`,{
  method:"POST",
  headers:{ "Content-Type":"application/json" },
  body:JSON.stringify({ hash, meta:{ type:"text" } })
}).then(r=>r.json());

Tip: hash bytes exactly (UTF-8, no hidden transforms). For large files, hash streaming (chunked) client-side.

4) Endpoints

POST /api/timestamp

Create a signed timestamp for a SHA-256 hash.

POST /api/timestamp
Content-Type: application/json

{
  "hash": "^[a-f0-9]{64}$",
  "meta": { "type": "file", "note": "optional" }
}

Response

{
  "hash": "^[a-f0-9]{64}$",
  "ts":   1730793600000,
  "sig":  "base64url(...)",
  "alg":  "HMAC-SHA256",
  "issuer":"timeproofs.io",
  "meta": { ... }
}

GET /api/verify

Verify a proof by hash.

GET /api/verify?hash=<SHA256_HEX>

Response

{
  "exists": true,
  "valid":  true,
  "hash":   "…",
  "ts":     1730793600000,
  "sig":    "…",
  "alg":    "HMAC-SHA256",
  "issuer": "timeproofs.io",
  "meta":   { ... }
}

Signature policy: HMAC-SHA256 over ASCII hash|ts, Base64URL without padding.

FieldTypeRequiredDescription
hashstringyesLowercase hex SHA-256 of exact bytes
tsnumberyesUnix epoch milliseconds (UTC)
sigstringyesSignature of hash|ts
algstringyesSignature algorithm
issuerstringyesIssuer identifier
metaobjectnoSmall hints (avoid secrets/PII)

5) Proof format (.tproof.json)

Portable proof file you can store next to your artifact (works well for offline workflows).

{
  "version":"v0.2",
  "hash":"^[a-f0-9]{64}$",
  "ts":"2025-12-22T00:00:00.000Z",
  "alg":"HMAC-SHA256",
  "sig":"base64url(...)",
  "issuer":"timeproofs.io",
  "meta":{"type":"release","note":"optional"}
}

Offline: you can validate structure + compute hash match. Online: you can also confirm existence with /api/verify.

7) Best practices

Hashing rules

  • Hash exact bytes (UTF-8 for text, raw bytes for files).
  • Avoid hidden transforms (line endings, BOM, normalization).
  • For large files: hash streaming (chunked) client-side.

Meta hygiene

  • Keep meta small.
  • Never put secrets or personal data in meta.

If two people hash the same bytes, they must get the same SHA-256 — verification depends on it.

FAQ

Do you store my files? No. Only hashes. Original content never leaves your device.

Is a file timestamp enough? No. File dates are local and editable. TimeProofs proves existence of an exact hash at a time, with public verification.

Blockchain? No.
