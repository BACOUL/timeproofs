# TimeProofs AgentReady — Browser V1 QA Runbook

## Purpose

This runbook explains exactly how to complete the Browser V1 QA when a real browser is available, either locally or through a Vercel preview.

It does not mark Browser V1 as complete.

Browser V1 can only be marked complete after `docs/agentready/BROWSER_V1_QA_RESULT.md` is updated to PASS.

## Recommended QA modes

Use one of these modes:

```txt
Mode A — Local browser QA
Mode B — Vercel preview QA
```

Mode A is enough for product QA.
Mode B is useful when the project is reconnected to Vercel and credits/usage limits allow safe preview testing.

## Mode A — Local browser QA

### 1. Open the repository locally

```bash
git checkout timeproofs
git pull
```

### 2. Start a local static server

From the repository root:

```bash
python3 -m http.server 8080
```

Then open:

```txt
http://localhost:8080/
```

Do not use `file://` because browser fixture loading may fail.

### 3. Open DevTools

In Chrome or Edge:

```txt
Right click → Inspect
Open Console tab
Open Network tab
Check Disable cache while DevTools is open
```

Keep DevTools open during scanner and simulation flows.

## Mode B — Vercel preview QA

Use this only when Vercel is safe to reconnect or preview usage is acceptable.

### 1. Open preview URL

Use the preview URL generated by Vercel.

Example:

```txt
https://<preview-url>.vercel.app/
```

### 2. Confirm preview indexing safety

For a preview deployment, confirm it should not be indexed.

Check response headers if possible:

```txt
X-Robots-Tag: noindex
```

Do not treat preview SEO status as production SEO status.

### 3. Open DevTools

```txt
Console tab
Network tab
Disable cache
Preserve log optional
```

## Network tab verification

During all flows, the Network tab should only show:

```txt
HTML files
CSS files
JavaScript files
Local/static JSON fixtures
Static assets such as images/logo
```

It should not show calls to:

```txt
Uploaded API endpoints
MCP servers
LLM providers
Backend API routes
Payment providers
Account/session APIs
Dashboard APIs
```

If any live execution or backend requirement appears, Browser V1 must remain blocked.

## Export verification

Verify these files download successfully:

```txt
agentready.json
agentready-mcp.json
agentready-report.md
agentready-mcp-report.md
agentready-simulation.json
```

For PDF:

```txt
Use browser Print / Save as PDF.
Confirm the print dialog opens.
Confirm report content appears in print preview if available.
```

Use browser responsive mode or a real phone.

Check:

```txt
Navigation remains usable.

Buttons remain tappable.
```

## Fill the QA result

Update:

```txt
docs/agentready/BROWSER_V1_QA_RESULT.md
```

Use:

```txt
PASS — only if every blocking criterion is satisfied.
FAIL — if a blocking issue is confirmed.
PENDING — if QA is incomplete.
```

Do not mark PASS if:

```txt
Exports were not tested.
Network tab was not checked.
Test harness was not run.
Static simulation was not tested.
Mobile/narrow viewport was not at least smoke-tested.
```

## Mandatory limitation text

TimeProofs AgentReady does not guarantee that an AI agent will never fail.

It identifies structural risks that may cause AI agents to misuse APIs, tools or MCP servers.
