# TimeProofs — Partner, IP & Moat Loop Strategy

Status: CANONICAL STRATEGIC BASELINE

## Partner economics

A partnership must create concrete value for both sides. Supported models may include:
- reference/recommended integration;
- co-maintained provider pack;
- technical certification/interoperability proof;
- bundled managed usage;
- referral/revenue share only when justified by measurable distribution;
- authoritative evidence access for RESOLVE.

Do not pay for vanity partnership badges with no distribution, evidence access or customer value.

## Preferred partner outcome

Provider/platform exposes authoritative execution state or stable integration semantics; TimeProofs maintains cross-system invariants/resolution and becomes a neutral integrity layer distributed to downstream developers.

## IP / naming / licensing gate

Before broad public M9/release:
- verify TimeProofs trademark/name conflict risk in relevant software/infrastructure classes;
- confirm control of critical domains/social/package namespaces where practical;
- inventory third-party licenses and protocol/schema licenses;
- ensure public fixtures/examples can legally be redistributed;
- freeze license for core/public packs;
- freeze commercial terms for proprietary packs/resolvers;
- document contributor/IP policy before accepting substantial external contributions.

No repository document should imply registered trademark ownership unless actually obtained.

## Moat telemetry loop

Goal: turn operational learning into reusable compatibility knowledge without making raw customer payload custody the moat.

Preferred loop:

production event
→ privacy-safe failure classification
→ candidate edge case
→ human/automated reproduction with synthetic or sanitized data
→ regression fixture
→ pack/resolver improvement
→ versioned release
→ all customers benefit

Potential telemetry fields:
- pack/provider/version;
- invariant/resolver ID;
- outcome class;
- UNKNOWN/failure reason;
- latency/retry class;
- anonymous environment capability profile;
- whether a reported false block was confirmed.

Do not collect raw credentials, payment instruments or full transaction payloads by default.

## Quality over volume

A million opaque events are less defensible than a maintained corpus of verified provider semantics and regression cases. The moat metric is trusted reusable knowledge, not data hoarding.
