Verify a proof (POST /api/verify)

POST https://api.timeproofs.io/api/verify
Content-Type: application/json
Accept: application/json

{
  "bundle": { ...the .tproof.json content... }
}

Stateless by design: verification is proof-file based.

Proof file (.tproof.json, v0.2)

{
  "version": "timeproofs-0.2",
  "hash": {
    "algorithm": "SHA-256",
    "value": "sha256-hex"
  },
  "timestamp": {
    "issuedAt": "2025-11-04T10:22:33.123Z",
    "issuer": "https://api.timeproofs.io",
    "nonce": "hex-128bit"
  },
  "proof": {
    "algo": "Ed25519",
    "signature": "hex-signature",
    "publicKey": "base64-public-key (informational)",
    "keyId": "tp-v0-2-main"
  },
  "meta": {
    "type": "document",
    "source": "web:verify"
  }
}

A proof contains only hash + timestamp + signature fields. Verifiers trust the server key for keyId (publicKey is informational).

Quick FAQ

Is my content stored?
No. Only the hash circulates. The original content never leaves your device.

Why no blockchain?
Predictable latency, costs, and independent verification without third-party consensus layers.

How to verify in v0.2?
Load a proof file. Optionally load the original file to confirm it matches the proof hash. The API verifies cryptographic integrity without any storage.

Compliance?
Privacy-first, hash-only. See Regulations & Compliance.
