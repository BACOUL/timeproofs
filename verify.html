How it works

      
    
        
  1. Hash locally. For text and files, the browser computes SHA-256 on-device.
    2. 
        
  2. Timestamp via API. The tool sends only the hash, label and minimal meta to /api/timestamp.
    3. 
        
  3. Get a proof. The API returns JSON with the hash, UTC timestamp, signature and a stable verify URL.
    4. 
        
  4. Verify later. Anyone can hit /api/verify?hash=… or share /verify.html?hash=….
    5. 
      

    


    
    

      
API & cURL quickstart


      
Create a proof (server-side)


POST https://api.timeproofs.io/api/timestamp
Content-Type: application/json

{
  "hash": "7c040f8633b8...",
  "type": "release",
  "meta": { "source": "docs-example" }
}

      

curl -sS -X POST "https://api.timeproofs.io/api/timestamp" \
  -H "Content-Type: application/json" \
  -d '{"hash":"7c040f8633b8...","type":"release","meta":{"source":"docs-example"}}'


      
Verify a proof


GET https://api.timeproofs.io/api/verify?hash=7c040f8633b8...

      

curl -sS "https://api.timeproofs.io/api/verify?hash=7c040f8633b8..."

FAQ

      
Do you ever see my content?
No. Only the SHA-256 hash is sent to the API.

      
Can I verify without this page?
Yes. Use /api/verify?hash=… directly, or build your own UI.

      
Which hash algorithm?
SHA-256 today. Future spec versions may support more, always explicit in the proof.

      
Is this compatible with ProofSpec?
Yes. This tool is the reference implementation of the ProofSpec v0.1 contracts.
