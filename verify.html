URL calls (GET)

Simple verify via query string. JSON responses.

Verify by URL

GET https://api.timeproofs.io/api/verify?hash=<SHA256-hex>
Accept: application/json

Example

curl -sS "https://api.timeproofs.io/api/verify?hash=7c040f8633b8..." \
  -H "Accept: application/json"

Tip: you can share /verify.html?hash=<hash> as a public verification link.

Bundle .tproof.json

A portable file that contains the proof, not the content. Shareable and verifiable anywhere.

Schema

{
  "version": "v0.1",
  "hash": "sha256-hex",
  "algorithm": "SHA-256",
  "timestamp": "2025-11-05T10:22:33.123Z",
  "signature": "base64/hex",
  "signer": "TimeProofs",
  "meta": { "source": "web:verify", "filename": "optional" }
}

Create the bundle client-side

const bundle = {
  version: "v0.1",
  hash: proof.hash,
  algorithm: "SHA-256",
  timestamp: proof.timestamp,
  signature: proof.signature,
  signer: "TimeProofs",
  meta: proof.meta || {}
};
// JSON.stringify(bundle) and save as .tproof.json

Quick FAQ

Is my content stored?
No. Only the hash is sent. Your original file never leaves your device.

Why no blockchain?
For sub-100 ms latency, predictable cost, and simple public verification.

Offline verify?
v0.1 uses the API. v0.2 will add offline/bundle verification.

Regulatory stance?
Privacy-by-design, hash-only. See Regulations & Compliance.

How it works in simple terms

  1. Hash locally: we turn your file or text into a short fingerprint (SHA-256). This cannot be reversed to get your content.
  2. Timestamp via API: our server signs the fingerprint with a time. This proves it existed at that moment.
  3. Verify publicly: anyone can check the fingerprint and signature later. If your content changes, the hash changes.

You can share the public link we give you. People can verify without seeing your original content.
