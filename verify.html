URL calls (GET)

Simple verification via query string. JSON responses.

Verify by URL

GET https://api.timeproofs.io/api/verify?hash=<SHA256-hex>
Accept: application/json

Example

curl -sS "https://api.timeproofs.io/api/verify?hash=7c040f8633b8..." -H "Accept: application/json"

Tip: you can share /verify.html?hash=<hash> as a public verify link.

JSON contracts

Request/response bodies. See OpenAPI.

Create (POST /timestamp)

POST https://api.timeproofs.io/api/timestamp
Content-Type: application/json
Accept: application/json

{

  "meta": { "source": "web" }

Bundle .tproof.json

Portable file that contains the proof, not the content. Shareable and verifiable anywhere.

Schema

{
  "version": "v0.1",
  "hash": "sha256-hex",
  "algorithm": "SHA-256",
  "timestamp": "2025-11-04T10:22:33.123Z",
  "signature": "base64/hex",
  "signer": "TimeProofs",
  "meta": { "source": "web:verify", "filename": "optional" }
}

Create the bundle on client

const bundle = {
  version: "v0.1",
  hash: proof.hash,
  algorithm: "SHA-256",
  timestamp: proof.timestamp,
  signature: proof.signature,
  signer: "TimeProofs",
  meta: proof.meta || {}
};
// JSON.stringify(bundle) then save as .tproof.json

The “Download .tproof.json” button uses the latest “Create” response.

Quick FAQ

Is my content stored?
No. Only the hash circulates. The content never leaves your device.

Why no blockchain?
For <100 ms latency, predictable costs, and simple public verification.

Offline verify?
v0.1: via API. v0.2: offline/bundle mode planned.

GDPR / AI Act?
Privacy-by-design, hash-only. See Regulations & Compliance.
