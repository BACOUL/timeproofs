TimeProofs Public Keys

TimeProofs publishes public key metadata so future Action File Seals can be verified independently without sending sensitive action content to TimeProofs.

Open key registry JSON Read security policy
This page currently documents the public key publication model. The bundled key registry contains placeholder public key material until production signing is enabled. It contains no private key material.

Purpose

A future TimeProofs Seal signs a canonical payload hash, not the raw Action File content. A verifier can recompute the payload hash locally, load the matching public key, and check whether the Seal signature is valid.

The public key registry is published at:

/.well-known/timeproofs-keys.json

Key metadata fields

Field Purpose
public_key_id Stable identifier referenced by each Seal. It must never be reused for different key material.
algorithm Signature algorithm. The preferred future algorithm is Ed25519.
public_key Encoded public key material used by verifiers. Private keys must never appear here.
created_at Timestamp indicating when the public key entry was created or first published.
status One of active, retired, or compromised.
production_ready Indicates whether the key is real production material. Placeholder entries must set this to false.

Key status policy

Active

Can verify currently issued seals if production_ready is true. Active key IDs must be stable.

Retired

No longer used for new seals, but kept published so older seals can still be verified.

Compromised

Must stay listed with clear guidance. Verifiers should treat it as an incident state, not a normal valid key.

Private key rule

Private keys must never be committed, logged, included in CI artifacts, sent to clients, or published in the public key registry.

  • Production private keys belong in secure environment variables, secret managers, or dedicated key management infrastructure.
  • Demo keys, if ever used, must be marked as unsafe and must never be used for production seals.
  • Production signing must fail closed if key material is missing or invalid.

Verification limits

A valid public key verification can confirm that a Seal payload was signed by the corresponding issuer key and that it references a specific payload hash.

It does not prove AI correctness, legal validity, regulatory compliance, completeness of the underlying business facts, or acceptance by a court, regulator, insurer, bank, auditor, or partner.
